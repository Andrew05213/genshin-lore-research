# 构建空间：R0布局与最终索引映像

本轮从 `e231872` 验证两项存储变化。它们不改变 Schema20、上游范围、模型、物理occurrence数量或Research工具合同。正式部署与旧receipt不原地修改；本文件的实际性能结果须由新的完整来源实验补充。

- 完整构建显式选择 [R0 storage v2](contracts/r0-storage-v2.md)，把重复的文件级身份保存在既有 `source_file` 中，逐条保留occurrence ID、文件ID、ordinal、pointer与SHA。读取视图返回原八列。
- Research默认不做VACUUM。保留构建连接中的完整来源oracle，再关闭、刷盘，以新只读连接检查最终映像；验证期间及发布后的SHA必须一致。`--compact-index` 显式保留压缩模式，仍接受相同完整核验。
- 新模式的完整基础构建预检20 GB，含向量22 GB；显式VACUUM保持26/28 GB。索引独立构建分别预检7/14 GB，向量独立构建2 GB。这些是额外预算，项目hard limit仍是90,000,000,000 B。新峰值须经真实构建验证，不能把修改门禁本身算作释放空间。

两组完整对照在新目录顺序运行，固定来源、历史来源、依赖及模型，均使用 `--jobs 3 --embedding-threads 4 --textmap-cache-mib 1024`。不清操作系统页缓存，每组一次，不包含下载。采样同时记录输出文件、同进程树仍持有的已删除临时文件和RSS，不能用最终目录大小冒充峰值。

控制组使用 `e231872` 的原默认模式；候选使用新默认。完整来源oracle、R0逐字段行集、文本物理坐标/正文、向量映射及MCP分页/引用分别核对。不同artifact的SHA和依赖字节的派生run按既有规则记录，不重标旧ref，也不通过显示文本相同合并身份。

构建参数见 [完整指南](guides/building-dataset.md)。不在本轮压缩模型、量化向量、删减来源或取消验证；Research索引中其他重复元数据仍保留，未宣称全部存储冗余已消除。
