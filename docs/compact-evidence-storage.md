# 构建空间：R0布局与最终索引映像

固定来源的两次完整新目录构建验证了两项存储变化：R0 文件级身份归一化，以及取消必需的 Research VACUUM。Schema20 版本、来源范围、模型和 Research 工具合同不变，正式部署与旧 receipt 不原地修改。机器可读结果与本地原始记录摘要见 [测量记录](reviews/compact-evidence-storage.json)。

## 同条件结果

Linux、Python 3.12.3、SQLite 3.45.1；控制组 `e231872`，候选 `5495c0d`。固定同一份来源、历史来源和本地模型，两组均为 `--jobs 3 --embedding-threads 4 --textmap-cache-mib 1024`，默认包含向量。按控制组、候选组顺序各执行一次，输出为空且不复用阶段；不清操作系统页缓存，不包含下载。可用预算按每次全项目实测填写，均未触及限制。

| 指标 | 控制组 | 候选组 | 变化 |
|---|---:|---:|---:|
| 完整进程耗时 | 2,270.51 s（37:50.51） | 2,138.49 s（35:38.49） | -132.02 s / -5.81% |
| 观测构建峰值 allocated | 25,529,147,392 B | 16,492,498,944 B | -9.04 GB / -35.40% |
| 完整输出 allocated | 19,805,179,904 B | 16,492,498,944 B | -3.31 GB / -16.73% |
| R0 数据库 | 4,711,841,792 B | 1,305,411,584 B | -72.30% |
| Research 索引 | 6,569,615,360 B | 6,662,774,784 B | +93,159,424 B |

GB 为十进制。空间采样每 0.5 秒记录输出目录和本进程树持有的已删除临时文件，按 device/inode 去重；控制组峰值包含约 6.55 GB 的 VACUUM 临时文件。worker 生命周期中有 109/182 次 PermissionError 采样空档，原始记录保留，两个峰值采样点均无缺项。这里报告的是观测峰值，不是已证明的最大上界；没有用最终目录大小代替控制组峰值。RSS 为进程树相加的采样值，可能重复计算共享页，分别约 6.28/6.69 GB，未宣称内存下降。

控制组 VACUUM 耗时 44.95 秒。R0 构建、封存及独立核验从 551.02 降至 494.59 秒；索引对应阶段从 587.06 降至 546.51 秒。并行阶段耗时不能相加作为关键路径收益；35:38 仍未达到 30 分钟，不保证其他机器相同提速。

## 验证与身份

两组均通过 35 个 exact inputs、33 个 core providers、60 个数据库阶段及默认向量构建；两次索引完整来源 oracle 的结果各自完全一致。

- R0 的 162,309 个文件与 14,401,737 条 occurrence 逐字段行集相同，含原 snapshot/parser/run、ID、ordinal、pointer 和原 token SHA。
- 全部 3,761,013 条文本的物理坐标和原文多重集一致；全部关系、候选与来源绑定由各组独立完整 oracle 核对。
- 106,589 个来源窗口按完整物理坐标对齐后，向量值完全一致，最大差为 0。vector ID 顺序不同，没有宣称向量文件字节相同或合并重复 occurrence。
- 两组实际 stdio MCP 五工具、Book/Story 续读、范围引用与对白 cursor 检查通过；候选另通过 literal/lexical/semantic/hybrid 回读与 inspect、默认 literal 一致性和无重复分页检查。

最终本地合成回归 681 项通过，另有 7 项原生 HNSW 测试通过；编译、六命令 help、文档链接和 Apache-2.0/wheel 元数据检查通过。打包使用已有开发环境，未改变数据构建依赖。PR 的 Ubuntu/Windows CI 单独执行，不把合成 CI 写成 Windows 完整来源验收。

新文件使用新 size/SHA；依赖 artifact 字节的派生 run/ref 编码按既有绑定生成，不能用正文相同将旧 ref 重标到新库。正式 release、日常配置和原有 WIP 均未修改。完整来源成功不等于自动晋级正式产品，也不证明全游戏覆盖。

## 实现与复现

- 完整构建显式选择 [R0 storage v2](contracts/r0-storage-v2.md)，把重复的文件级身份保存在既有 `source_file` 中，逐条保留occurrence ID、文件ID、ordinal、pointer与SHA。读取视图返回原八列。
- Research默认不做VACUUM。保留构建连接中的完整来源oracle，再关闭、刷盘，以新只读连接检查最终映像；验证期间及发布后的SHA必须一致。`--compact-index` 显式保留压缩模式，仍接受相同完整核验。
- 新模式的完整基础构建预检 20 GB，含向量 22 GB；显式 VACUUM 保持 26/28 GB。索引独立构建分别预检 7/14 GB，向量独立构建 2 GB。这些是额外预算，项目 hard limit 仍为 90,000,000,000 B；本次真实观测支持预留裕度，不将降低门禁本身计为释放空间。

复现时分别检出上述实现，在不同空输出目录运行 [完整构建命令](guides/building-dataset.md)，固定来源、模型及以上参数。控制组保持原默认，候选保持新默认；不要在候选组加入 `--compact-index`。计时包含单个完整命令，额外的对照导出、MCP 检查和测试不计入构建墙钟。原始日志、回执、oracle 与比较导出留在实验机器，Git 仅保存代码和不含游戏正文的测量记录。

为避免峰值叠加，控制组资格验证与完整对照导出后，按精确清单退役 62 个可重建数据库/ANN/词典文件；旧实验的同类 62 个冗余文件也已退役。622 份保留记录逐项复核 SHA，原始失败、回执、向量值和完整坐标导出未删。正式与 legacy 输入不在清单中。

项目最终约 69.73 GB allocated，距 90 GB 上限约 20.27 GB，低于 warning。盘点沿用全项目及相关临时路径，并补记此次编译缓存约 12.44 MB；未通过挪目录缩小口径。再做一轮完整新目录构建，应先按留存规则退役当前可重建实验库，不能直接叠加一份。

未运行原生 Windows 完整来源计时，也未额外执行候选的完整来源 `--compact-index` 构建；显式压缩路径有合成回归，控制组执行了完整来源压缩。合成测试不能代替这些未运行项。不压缩模型、不量化向量、不删减来源、不取消验证；Research 索引中其他重复元数据仍保留，未宣称全部冗余已消除。
