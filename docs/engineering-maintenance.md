# 工程维护范围

本次修改面向公开源码构建，不改变已部署的正式 release、数据范围或 evidence ref。

## 可读性与复杂度

- 整理正在维护的构建调度和 Research 查询模块，将密集单行控制流展开为普通 Python；不批量格式化历史解析器。
- 构建阶段和峰值预算使用命名常量。来源解析仍按 family 分开，独立验证器不调用构建器的投影算法。
- 保留来源清单、SQL 和历史模块。已有导入调查未证明可安全删除的实现，不凭文件数量或旧名称清理。
- 后续平台与性能修改使用同一条构建路径，不新增调度框架、插件系统或缓存服务。

## 验证层次

无游戏数据测试、真实来源重建、向量重建和正式发布验收分别记录。历史成功不能替代修改后实现的独立核验；失败与未执行项必须保留。

项目继续采用源码 checkout 分发，许可证保持 Apache-2.0。机器路径、数据库、游戏正文、模型和向量不进入 Git。

## 平台、性能与默认向量阶段

平台原语集中在一个小模块：真实锁、文件持久化边界和进程指标，不把平台兼容分散成业务分支。Windows 使用原生 CI，不能用 Linux 或 WSL 结果背书。

core 合同回填从每表最多 33 次扫描改成每表一次临时精确查表，永久 schema 和完整行集不变。[三次同条件局部对照](history/core-reconciliation-performance.json) 中位数为 0.49655 秒与 0.14840 秒；不是整库提速声明。阶段回执新增 builder、verifier/封印、末尾资格耗时，便于后续按实际瓶颈优化。

保守的实现身份范围暂不缩窄。缺少可靠依赖证据时，将其改成精巧的自动追踪或缓存系统，风险高于收益；不能为提高恢复率漏掉解析器、验证器或合同变化。

默认完整构建纳入既有模型的独立 overlay；显式模型取得、选择范围、完整来源 oracle 与新输出配置见 [向量构建](guides/building-semantic.md)。基础数据、向量构建和正式发布验收仍然分别判断。
