# 调查查询性能优化

2026-11-09，在原生 Windows、同一份已构建 7.2 语料和固定本地模型上，对主线 `99187fd1fafae384b9870952c49029fbfb7eddff` 与运行时优化 `7eb17cca1f6ac7ff9d08f84fe38b621033346da0` 做同条件对照。这里只改变查询路径，不改变构建器、schema、原文、向量或 seal。

## 改动

- Codex 对白标题查询按既有 `(container_id, ordinal, id)` 索引取行，再恢复原来的 ID 展示顺序，避免为每个节点扫描整个语言范围。逐条来源 slot、原文及角色标注检查仍执行。
- 覆盖统计缓存固定索引的来源键集合。缓存属于单个只读、immutable 的 ResearchQuery 连接，以 SQL 和参数为键；family 顺序/重复规范化，最多 128 项 LRU，无 TTL 或持久化文件，关闭连接时释放。换语料必须新建连接。
- 缓存值是不可变集合；返回列表、当前不可用状态、adapter coverage 状态和未知范围每次重新组合。正文、证据关系、引用与完整性校验不从这份元数据缓存获得豁免。

## 实测

每种工作负载按 A-B-B-A 串行执行，每侧两次新进程；Windows 文件缓存未清空。表格为小样本中位数，n 是每侧调用数，不能当作 p95 或所有调查的表现。姓名路径每页 3 个节点，已定位对白路径每页 1 个节点；不同路径不按页面大小直接比较。

| 路径 | n | 主线 | 优化后 |
|---|---:|---:|---:|
| 29 次姓名工作负载（含启动） | 2 | 100.5352s | 23.7756s |
| 姓名搜索：进程首次 | 2 | 9.7290s | 3.2265s |
| 姓名搜索：同进程后续 | 6 | 8.9765s | 0.4269s |
| 姓名进入对白 | 8 | 5.1939s | 0.3449s |
| 姓名 cursor 续页 | 8 | 5.2214s | 0.3883s |
| 姓名对白上下文 | 8 | 1.7235s | 0.0952s |
| 普通 literal：进程首次 | 2 | 1.9064s | 1.8468s |
| 普通 literal：重复 | 4 | 1.8864s | 0.0027s |
| semantic：首次模型查询 | 2 | 4.5802s | 1.3948s |
| semantic：重复 | 2 | 3.4570s | 0.0287s |
| hybrid | 4 | 5.4699s | 1.9090s |
| 新进程 initialize | 4 | 15.3370s | 15.0004s |

首次姓名搜索是每个进程先执行的同一姓名入口；后续搜索包含换姓名后的请求。首次普通 literal 仍需填充元数据缓存，不能把重复请求的降幅用于首次请求。semantic 的首次模型查询发生在 literal 样本之后，因此覆盖缓存已热；首次模型加载成本仍包含在内。启动 seal/来源/模型哈希照常执行，未将其跳过来获得提速。

## 验证范围

两侧各 132 次实际 MCP 调用，五工具均执行。按返回 action/cursor 读取正文、续页、上下文、前驱与单条/批量 inspect；semantic/hybrid 仍是显式候选发现。所有调用的完整响应、请求参数、顺序、分数、正文与 provenance、覆盖/候选限制、cursor 和 action 均逐项相等；仅归一化随机会话 handle 前缀及依赖该会话的 receipt digest。原始私有记录保留本地。

优化提交的本地完整无游戏数据回归：**857 通过、11 跳过**；另有编译、六命令 help 和 wheel 检查。新增合成回归覆盖标题 ID/ordinal 顺序差异、来源损坏拒绝、语言/family/连接隔离、动态 unavailable/coverage 状态、空集合命中和有界淘汰；完整套件包含新建合成索引、独立 oracle 与真实 MCP 子进程。跳过来自 Linux/POSIX/Bash 分支及本机符号链接权限，不增加跳过项。

一个自然问题的原生 Codex 新会话通过进程级 MCP 参数指向候选源码，实际执行五工具、正文预览、严格 cursor 续读和来源卡核对；3 条引用又经新进程回读/inspect，正文精确范围与 provenance 一致。该会话是功能观察，不是模型速度 A/B 或一般回答质量保证。原生 citation renderer 没有改变。

首轮定向测试有 5 项因系统临时目录权限在 fixture 设置阶段失败；保留现场后改用新的项目内临时目录，78 项定向复验通过。完整来源数据库未重建，旧构建回执没有重签，也不把旧字节当作优化提交的冷构建成功。实际来源验证限于既有合格数据上的只读运行兼容与有界 MCP A/B；没有修改数据生成 SQL。Linux 原生执行、Desktop GUI 重启、多客户端并发及长期内存峰值未运行。本次未切换持久 MCP 配置、发布安装包或合并 main。
