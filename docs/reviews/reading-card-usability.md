# 阅读卡与上下文交付改进

本次变更基于 PR #21 合并后的源码，复用既有数据库和五工具，不改变数据范围、排名、证据身份或发布资格。

## 行为

- Markdown 阅读卡只显示已有标题、正文及必要的来源角色标注。完整原文、SHA、范围、状态、原 read mapping 和正式 inspect 保存在独立 JSON；已交付旧卡片不覆盖。
- `inspect_evidence(evidence_refs=[...], save_source=true)` 对1–32个明确选择独立核验，成功后生成一张卡。任一核验失败则不保存集合，逐项结果保留。不同 observation、范围、物理记录不按相同文字合并；选择顺序不等于剧情顺序。
- 普通单条 inspect 仍默认 full；批量/保存默认精简。默认 read 省略重复技术结构，保留正文、标题、角色状态、候选限制、范围和 cursor；full 与私有记录保留原证据。
- 对白返回可直接执行的续页及节点上下文动作。分页参数仍绑定原 anchor、locale、limit 和 detail；上下文阅读不推断时间顺序。
- 人物面板按材料类型组织；即使当前页只有介绍/正文而未出现姓名行，也可做一次既有 Character 精确姓名查找，读取有界 Story/Voice 候选。过滤请求不扩出范围，原始命中/排序/cursor 不变。
- 使用 SDK 公开 Context 发送搜索/读取阶段及逐项核验的进度通知。它不是正文流式返回，显示取决于客户端；未改原生 Codex renderer、单次 SQL 取消或客户端重复展示机制。

## 实际核对

本地同一固定 v1.1 数据经真实 stdio MCP 分别运行合并基线与修改源码；没有重新构建索引。相同对白首屏2个主节点：

| 项目 | 基线 | 修改后 |
| --- | ---: | ---: |
| 序列化 reading 响应 | 24,192 B | 14,717 B |
| 单条卡片 Markdown | 5,240 B | 132 B |
| 保存响应 | 4,804 B | 1,782 B |
| 人物正文预览 | 5 | 5 |
| 请求进度的测试客户端收到通知 | 0 | 15 |

正文 SHA 顺序一致；两条实际正文一次保存为一张卡，逐条 provenance 与 full 正式检查一致。返回的 next-page/context 动作经 MCP 实际调用通过。另一次现有 `check_dialogue` 检查通过，覆盖五工具、两页正文及来源一致性、cursor 拒绝与卡片回读。

每侧一次体积测量，不构成广泛性能跑分或用户等待提速结论。首次改动因附加续页动作曾使 reading 响应增至24,906 B；该记录保留，随后仅消除重复的角色/容器技术结构，得到上表结果。

合成回归覆盖集合选取、范围及 observation 独立性、无效/跨连接句柄、完整检查记录、失败不保存、实际 stdio 进度、工具注册、正文续页和上下文动作。原有管线两项测试因假定默认携带 full provenance 失败，原记录保留；现分别读取 reading/full 严格比对，并继续比对卡片 JSON 中的正式 provenance，没有删除断言或降低门槛。

最终 Linux 合成回归771项通过、3项跳过；受影响的协议、来源卡、展示、引用交付及仓库规范定向检查70项通过。编译、Markdown本地链接、六命令help、元数据及 Skill 结构检查通过。新增范围检查保证同一ref的不同observation不因同文而省略正文。

本地 wheel 检查未执行成功：验证环境缺少 `build` 和 `pip` 前端模块，诊断保留；没有为展示改动修改依赖或下载新的安装工具。两端打包及 Windows 回归由新分支 CI 单独检查，不将此前 main 的 CI 结果充当本次结果。

初轮分支 CI 中 Linux 771项通过、3项跳过，Windows 766项通过、8项跳过；两端编译、wheel、命令与依赖包检查均完成。Windows job 总耗时15分6秒，仍因15分钟上限被标记为取消，不能将该job结论写成成功。原[运行记录](https://github.com/Andrew05213/genshin-lore-research/actions/runs/41470159033)保留；仅将Windows完整job预算调整为20分钟，Linux保持15分钟，测试命令、断言、失败条件均不变。

本轮未执行新的真实模型剧情矩阵或完整35输入重建；这两项不是本次展示改动的成功声明。原始调用与游戏正文只保留在本地私有验证目录，不提交仓库。

接口及操作见 [对白阅读指南](../guides/reading-dialogue.md)。本地默认 MCP 不随分支提交自动部署。
