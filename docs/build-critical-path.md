# 完整冷构建的后续优化

本轮在已合并的 `60ce13c` 上验证两个候选改动：Core 完成后在空闲 worker 中执行 Codex，以及将普通查询索引延后到投影完成后建立。主键、唯一性约束、完整来源 oracle、压缩后复验与发布资格保留。

性能验收预先固定为同机、顺序执行的两个完整新目录构建，控制组和候选组都使用 `--jobs 3 --embedding-threads 4 --textmap-cache-mib 1024`，固定同一来源、历史来源、依赖与模型。每侧一次，不清操作系统页缓存，不含下载。完整构建期间不并发运行其他本轮重任务。

控制组验证完成后，可按留存规则退休其可重建数据库；保留全部日志、回执、来源 oracle、物理文本 multiset 摘要及向量对照材料。再次测量项目容量后才开始候选组。两侧均须完成来源核对和运行时 smoke，不能以退出码或耗时替代。

此外，线程数只进行小范围推理调度诊断，不改变本轮完整对照的四线程设置。未完成的实验不得宣称冷构建提速。
