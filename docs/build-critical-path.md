## 保留的改动

- Core 完成后，在既有 worker 空位内运行 Codex；所有依赖和回执核对继续执行，失败仍停止并等待整个 worker 树。没有提高 worker 上限或引入通用调度器。本次 Codex 到约 358 秒才取得空位，与主线程小型组件重叠，约 503 秒被观察到完成；并不是把它约 144 秒的自身耗时全部从总时间中扣除。
- 投影期间保留主键和物理身份唯一性约束，七个非唯一查询索引在投影完成后集中建立，再执行 FTS 和完整 oracle。独立核对冻结 main 与候选的最终 `sqlite_master` 定义完全一致；新增负测同时覆盖重复主键和不同主键的重复物理身份。

保守默认仍是 `--jobs 2`；上面的性能结果使用显式 `--jobs 3`。没有修改模型、精度、推理批次、来源范围、验证门槛、MCP 工具或默认 literal 搜索。Codex 自身在争用下从约 131 秒增至 144 秒，收益来自有限重叠，不宣称并行总会加速。

## 来源与运行验证

两侧各自通过完整来源 oracle：921,382 containers、3,761,013 texts、663,590 relations、446,132 candidates；84 个声明的完整关系/候选范围仍逐项核对。压缩前后两次完整验证均保留。

补充全量比较每条文本的 family/contract、物理容器与文本坐标、来源文件 seal、locale、字段角色、ordinal 及实际原文，保留重复项数量。**3,761,013 条文本的物理坐标与原文 multiset 一致。** 按物理坐标和窗口范围对齐，**106,589 个 float32 窗口向量数值全部一致，最大差为 0**；两侧 vector ID 顺序不同，不按数组下标盲比，也不宣称 signed-zero 等位表示完全一致。

不同输出目录的派生 parser/run、索引 SHA 和部分引用封装可能不同。上述对照没有重标旧 ref、合并逻辑身份或代替两侧独立来源验证。

实际 stdio MCP 通过五工具调用、Book 85 行分 12 页到当前文件 EOF、Story 400..576 字符范围与 inspect、对白两页及错误 cursor 参数拒绝。literal/lexical/semantic/hybrid 均实际 read/inspect，默认 literal 与显式 literal 一致，搜索分页不重复。这里只证明程序化 transport/readback，没有运行新的模型自主答案矩阵或正式发布验收。

本轮 669 项合成回归通过；最终 worker/仓库定向检查 38 项及实际 hnswlib 合成检查 7 项通过。实现提交的 Ubuntu/Windows CI 各 669 项通过，重点模块覆盖率 77%；编译、公开入口 help、链接、许可、wheel 和代码/依赖包检查通过。原生 Windows 完整来源性能未运行，不用 CI 合成测试替代。

## 未采用的方向与留存

所有完整计时和其他重检查结束后，另从候选中均匀选取 4,096 个真实窗口，以 4→6→6→4 线程顺序进行独立暖模型诊断。固定 batch 32，计入 token 分组成本，模型初始化不计入该局部计时；4 线程中位数 21.500 秒，6 线程 19.748 秒，减少 8.15%，四次向量数值全部一致。这只是固定 8 CPU 环境中的局部信号，不是完整构建的重复次数或提速结论。已有参数 `--embedding-threads 6` 可显式试用，本轮默认和完整 A/B 仍保持四线程；没有据此宣称 6 线程全量重建通过。

独立热点分析中，完整来源 oracle 的时间分散在全量行读取、SQL、物理坐标/正文比对和哈希；runtime smoke 的主要成本也包括真实 artifact seal 与查询。没有删除检查或建立跨请求信任缓存。最初误配旧部署索引的 oracle 诊断失败、错误测试文件名和线程初探的并发干扰均保留在本地，不计作来源重建失败，也不用于提速声明。

控制组完成资格后，退休其 62 个可重建数据库/ANN/lexicon 文件，保留 308 份原始记录、完整物理对照导出、metadata 与原向量。候选完整输出保留；源快照、模型、部署数据、其他 worktree/WIP 和原失败证据不清理。项目存储政策仍为 90,000,000,000 B hard、77,309,411,328 B warning；两组顺序构建，未复制正式部署的大库。

## 复现

按 [完整构建指南](guides/building-dataset.md) 准备来源和模型，用各自干净代码与新输出目录顺序执行：

```sh
python scripts/build.py \
  --source data/AnimeGameData \
  --historical-source data/AnimeGameData-history \
  --model-cache data/model-cache \
  --output-root data/rebuilt-critical-path \
  --stage all --jobs 3 --embedding-threads 4 --textmap-cache-mib 1024 \
  --available-allocated-bytes HEADROOM_BYTES
```

`HEADROOM_BYTES` 是实际项目预算余量，至少满足 28 GB 预检，不能用主机空闲代替。两组输出路径不能相同；恢复已验证阶段不是冷构建。30 分钟仍需后续实测支持，不能从局部调度诊断推算已完成该目标。
